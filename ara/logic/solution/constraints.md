# Constraints

## Boundary conditions

- **PCA target-aware refit only activates for cross-device protocols.** `target_devices = test_devices - train_devices` is empty for `R_R`/`S_S`, so matched-device PCA behavior is byte-for-byte unchanged by the C05 fix — this is by construction, not a tested-and-confirmed equivalence (no explicit test asserts matched-device PCA outputs are identical pre/post fix, though the code path guarantees it).
- **CORAL and PCA both fit their target-aware component on unlabeled target-device *validation* subjects only, never test subjects.** This is enforced by construction (`target_val_idx` is built from `val_subjects`, a disjoint set from `test_subjects` per the fold-splitting assertion) — test-set information never enters any fit.
- **The corroboration filter never touches the test set.** Only `train_idx`/`val_idx` are filtered; `filter_uncorroborated_training` explicitly raises if applied against the main `P0_device_gap` results root, to prevent the ablation's differently-filtered runs from silently colliding with baseline dedup keys.
- **HeAR's fixed-input constraint governs its entire integration.** The model accepts only exactly 2.0s/16kHz/32,000-sample clips; every manifest window (regardless of true duration) is reduced to one such clip via center-crop-or-zero-pad (`extract_hear_features.py::to_fixed_clip`) — this is a real information-loss step for windows much longer than 2s, not a lossless summarization.
- **GPU-only execution is a hard, enforced constraint project-wide**, not merely a performance preference: `random_forest`/`svm_rbf` (cuML) fail natively with no CPU path; `xgboost`/`mlp`/HeAR each carry an explicit `torch.cuda.is_available()` / `tf.config.list_physical_devices("GPU")` check that raises rather than falling back. `classical` and `odi_hb` are the only two features exempt (`features.NO_GPU_NEEDED`), since neither involves model inference to accelerate. PCA/CORAL's own linear algebra (`sklearn.decomposition.PCA`, `scipy.linalg.eigh`) is CPU by design (small, one-shot-per-fold operations, not the bottleneck) and is a documented, deliberate exception to the policy, not an oversight.

## Known limitations

- **Significance testing lags the current representation set (G1).** Any claim in this ARA phrased as "X has the highest point estimate" (rather than "X is significantly higher") for a representation not in `{hubert, wavlm, wav2vec2, data2vec_audio, data2vec_spectrogram, full_fusion, data2vec_fusion}` (the set covered by the last `P0_statistics` run) should be read as a point-estimate-only finding until re-tested. This affects C01 and C08 most directly (HuBERT's ranking includes 3 untested-for-significance newer representations; HeAR's underperformance is likewise a point estimate against those newer representations, though its comparison to the *original* representation set would inherit the older, still-relevant significance machinery if re-run).
- **CORAL's scope (G3) is narrower than PCA's post-fix scope** — 3 representations x 1 classifier vs. PCA's 5 representations x 4 classifiers — so C06 (CORAL fails) is evidenced less broadly than C05 (PCA fix works). This asymmetry is itself worth closing before treating the two as directly comparable "one works, one doesn't" findings in a publication.
- **No external dataset validation exists anywhere in this project.** Every claim in this ARA is scoped to the single cohort (N=41-50 subjects depending on device-pairing/audio-availability) this pipeline was built around; generalization to other recording hardware, other clinical populations, or other annotation protocols is untested.
- **The sliding-window severity work (E09/C11) has no cross-device rows completed yet** as of this ARA's compilation — its 28/80 completed combinations are entirely matched-device (R_R, S_S). Any claim about its cross-device behavior would be pure extrapolation from E01-E03's general pattern, not direct evidence.
- **No manual clinical re-adjudication was performed** for the SpO2-corroboration audit's "uncorroborated" events (E06) — the interpretation that they are likely real, differently-scored positives (chest-effort/flow-scored hypopneas) rather than annotation errors is a plausible domain-knowledge-based inference, not independently verified against the original PSG scoring records.
- **The GPU-classifier ports are not claimed bit-identical to their CPU/sklearn origins** (A4) — cuML's RandomForestClassifier/SVC and the from-scratch PyTorch MLP are functionally analogous, not verified-identical, implementations. Any subtle numerical difference from a hypothetical CPU-only re-run of this entire benchmark is unquantified.
